# 编码 Skill

> 编写或修改代码、代码审核时加载此文件。

## 编码约束

1. **禁止修改已测试通过的代码** — 需修改时必须先提交修改申请
2. **单一职责** — 每个文件不超过 200 行，超过必须拆分
3. **类型注解必须** — 所有函数参数和返回值
4. **异常不吞没** — except 块必须至少包含日志记录
5. **配置驱动** — 可变参数从配置文件读取，不硬编码
6. **日志先行** — 关键步骤前后 DEBUG 日志，异常 ERROR 日志
7. **禁止全局状态** — 状态通过管理对象统一管理
8. **数据类优先** — 数据定义用 @dataclass，不用 dict
9. **中文注释** — 关键业务逻辑注释用中文
10. **禁止输出敏感信息** — 脱敏处理

## 架构约束

1. **依赖方向单向**：业务层 → 核心层
2. **事件驱动通信**：业务层间通过事件总线解耦
3. **插件接口稳定**：基类接口确定后不轻易修改
4. **向后兼容配置**：配置文件新增字段必须提供默认值

## 编码写作规范

- **字段注释格式**：涉及第三方数据源的字段统一使用标准注释格式，包含来源标注和适配说明（如有格式转换）。
- **流程校验优先**：回答问题前，先将问题和关联模块放入整体流程中按时间线校验，确认逻辑合理后再做回答。不得脱离上下文孤立作答。
- **第三方接口核实**：引用第三方库或外部数据源时，必须先到官方文档确认数据结构、接口参数等内容，再基于核实后的信息回答。不得凭记忆假设接口细节。
- **第三方依赖逻辑一致**：当前定义功能或逻辑与第三方库接近时，需考虑是否能与三方库接口或流程上一致。
- **再次确认问题**：输出回复内容前，再次检查回复内容是否解答了用户的问题。

## 工具链

```bash
ruff check .           # lint
ruff format .          # 格式化
mypy {package}/        # 类型检查
bandit -r {package}/   # 安全扫描
```

## 编码前检查

- [ ] 目标模块的上下文已加载
- [ ] 不修改已测试通过的代码（除非已获批准）

## 编码后检查

- [ ] `ruff check .` + `ruff format .` 无错误
- [ ] `mypy` 零错误
- [ ] `bandit` 无告警
- [ ] 全部测试通过
- [ ] 新代码有对应测试（覆盖率 > 85%）
