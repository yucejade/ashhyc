# 文档转 HTML Skill

> 将设计文档或技术文档转换为美观、可读的 HTML 页面。

## 适用时机

- 用户要求将文档转为 HTML 格式
- 用户要求生成可读的文档展示页面
- 用户要求"美化文档"、"可视化文档"等

## 核心原则

1. **忠于原文**：所有 HTML 内容必须忠实于源文档，不得遗漏、篡改、臆测内容。信息完整性优先于美观。
2. **人类可读**：页面设计以阅读体验为中心，使用颜色、图形、排版引导读者理解内容结构。
3. **简单美观**：用最少的元素达到最好的效果。不引入外部依赖（框架、字体库、图标库），纯内联 CSS + 原生 SVG。
4. **风格一致**：所有生成的 HTML 文件使用同一套设计系统（色彩、字体、间距、组件），确保项目文档站的整体一致性。

## 设计系统

### 色彩方案

深色主题，以深蓝灰为底，用五种强调色表达不同语义：

| 用途 | CSS 变量 | 色值 | 适用场景 |
|------|---------|------|---------|
| 主色 | `--accent-blue` | `#38bdf8` | 章节标题、事件名、导航 |
| 成功/通过 | `--accent-green` | `#4ade80` | 通过 ✓、正常路径、优先级高 |
| 警告/关注 | `--accent-amber` | `#fbbf24` | 阶段标记、时间点、中间状态 |
| 错误/失败 | `--accent-red` | `#f87171` | 失败 ✗、异常路径、风险项 |
| 次要强调 | `--accent-purple` | `#a78bfa` | 子标题、分组头、数据同步 |
| 辅助色 | `--accent-teal` | `#2dd4bf` | 三级标题、补充信息 |
| 辅助色 | `--accent-pink` | `#f472b6` | 关键值、字段名 |

基础色：

| 用途 | CSS 变量 | 色值 |
|------|---------|------|
| 背景 | `--bg` | `#0f172a` |
| 卡片/容器 | `--surface` | `#1e293b` |
| 二级表面 | `--surface2` | `#334155` |
| 边框 | `--border` | `#475569` |
| 正文 | `--text` | `#e2e8f0` |
| 次要文字 | `--text-dim` | `#94a3b8` |

### 字体

- 正文：`'Segoe UI', system-ui, -apple-system, sans-serif`
- 代码/流程树：`'Cascadia Code', 'Fira Code', monospace`
- 不引入外部字体文件

### 间距与圆角

- 页面边距：`2rem`
- 卡片内边距：`1.2rem ~ 1.5rem`
- 圆角：`8px`（小元素）~ `12px`（卡片/容器）
- 组件间距：`1rem`（小）~ `3rem`（大章节）

## 内容映射规则

将源文档的不同结构映射为对应的 HTML 组件：

### 文档结构 → HTML 组件

| 源文档结构 | HTML 组件 | 说明 |
|-----------|----------|------|
| 文档标题 + 元信息 | Hero 区域 | 渐变标题 + 副标题 + 状态徽章 |
| 章节目录 | TOC 导航栏 | Flex 横排按钮，锚点跳转 |
| 一级标题 `##` | 章节标题 | 左侧带色块图标 + 蓝色标题 + 底部分隔线 |
| 二级标题 `###` | 子标题 | 紫色文字，较小字号 |
| 三级标题 `####` | 三级标题 | 青色文字 |
| 统计数据/关键数字 | 统计卡片网格 | 大字号数值 + 说明文字 |
| 流程树（`├─`/`└─`） | 语法高亮流程树 | 等宽字体，颜色标注事件/订阅/通过/失败 |
| `=== 阶段名 ===` | 阶段标记 | 琥珀色加粗，独立行 |
| `▶` 事件订阅 | 紫色标注 | `.subscribe` 类 |
| 事件名（全大写） | 蓝色标注 | `.event` 类 |
| `✓`/`✗` | 绿/红标注 | `.pass` / `.fail` 类 |
| 表格 | 带样式表格 | 深色表头、行悬停高亮、分组头 |
| 典型场景表 | 场景表格 | 首列琥珀色加粗、末列灰色说明 |
| 关键设计点 | 渐变卡片 | 蓝紫渐变背景，三角符号列表 |
| 代码/配置块 | 配置块 | 等宽字体，语法着色（key/string/comment） |
| 安全分析 | 图标卡片列表 | 左侧彩色图标 + 右侧标题说明 |
| 优先级/等级 | 阶梯图 | 纵向排列，颜色从绿→黄→红渐变 |
| 时间线/生命周期 | 水平时间轴 | 圆点 + 连线 + 时间 + 标签 |
| 发布/订阅矩阵 | 矩阵表格 | ● 绿色发布，▲ 蓝色订阅 |
| 并列对比 | 卡片网格 | 左侧色条区分 |
| 徽章/标签 | 圆角胶囊 | 小字号 + 半透明背景 + 对应色文字 |

### 流程树语法高亮规则

流程树中识别以下模式并着色：

| 模式 | 颜色 | 示例 |
|------|------|------|
| `=== 文字 ===` | 琥珀色加粗 | `=== 启动 ===` |
| 全大写 + 下划线（事件名） | 蓝色加粗 | `SYSTEM_START`、`MARKET_TICK` |
| `▶` 开头的订阅行 | 紫色 | `▶ 数据层` |
| `✓`、`通过` | 绿色 | `通过 ✓` |
| `✗`、`失败`、`不通过` | 红色 | `不通过 ✗` |
| 注释/说明文字 | 灰色 | `（初版不处理）` |
| 配置键名、特殊值 | 粉色 | `signal_source="RISK"` |

## 模板结构

每个生成的 HTML 文件遵循以下结构：

```
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>{文档标题}</title>
  <style>
    /* 1. CSS 变量（完整设计系统） */
    /* 2. Reset */
    /* 3. 布局容器 */
    /* 4. Hero 区域 */
    /* 5. 导航 TOC */
    /* 6. 章节标题 */
    /* 7. 卡片与网格 */
    /* 8. 流程树 */
    /* 9. 表格 */
    /* 10. 安全/分析组件 */
    /* 11. 时间线 */
    /* 12. 配置块 */
    /* 13. 辅助类 */
  </style>
</head>
<body>
  <div class="container">
    <!-- Hero: 标题 + 副标题 + 状态徽章 -->
    <!-- TOC: 锚点导航 -->
    <!-- Section × N: 各章节内容 -->
    <!-- Footer: 文档元信息 -->
  </div>
</body>
</html>
```

## 转换流程

### 第1步：读取源文档

- 读取用户指定的源文档（通常是 `.md` 文件）
- 理解文档的整体结构和层次

### 第2步：结构分析

- 识别所有标题层级（一级、二级、三级）
- 识别所有内容类型（流程树、表格、列表、代码块、说明段落）
- 标记特殊元素（事件名、阶段标记、通过/失败符号）

### 第3步：组件映射

- 将每个结构元素映射到对应的 HTML 组件
- 流程树：按语法高亮规则着色，保留原始缩进
- 表格：添加分组头、着色单元格
- 段落/列表：转换为卡片或直接内容

### 第4步：生成 HTML

- 使用标准模板结构
- 所有样式内联在 `<style>` 中，不使用外部 CSS
- 不使用 JavaScript（纯静态 HTML）
- 文件与源文档同目录，扩展名改为 `.html`

### 第5步：自检

生成后对照以下清单检查：

- [ ] **内容完整性**：源文档的每个段落、表格、流程树都已转换，无遗漏
- [ ] **忠于原文**：未添加源文档中不存在的内容，未篡改任何信息
- [ ] **视觉一致性**：使用了标准设计系统的色彩、字体、间距
- [ ] **流程树着色正确**：事件名蓝色、订阅紫色、通过绿色、失败红色
- [ ] **表格完整**：所有行列都已渲染，分组头正确
- [ ] **导航可用**：TOC 锚点与章节 id 对应，点击可跳转
- [ ] **响应式**：卡片网格自适应，表格可横向滚动
- [ ] **无外部依赖**：未引入任何 CDN、字体库、框架

## 红旗 — 立即停止

- 源文档未完整读取就开始生成 HTML
- 为了美观而省略源文档中的内容
- 擅自"优化"或改写源文档的表述
- 引入外部 CSS/JS/字体依赖
- 偏离设计系统的色彩和组件规范
