# 会话退出

> 每次会话结束前调用，保存当前工作状态。

## 触发条件

当用户说出以下意图时立即触发：
- "bye" / "再见" / "结束" / "退出"
- "save" / "保存" / "先到这里" / "今天到这里"
- 或任何表明会话即将结束的信号

## 约束

- 与项目无关的闲聊、工具调试、环境配置等对话内容**不记录**到任何文件中
- 只记录与项目需求、设计、开发、问题排查直接相关的内容
- 不要主动 commit，由用户决定是否提交

## 执行步骤

### 1. 更新工作进度（.claude/schedule/schedule.md）
- 更新顶部 `> 更新:` 日期为今天
- 更新 `## 当前状态` 描述，反映最新进展
- 在对应阶段条目下追加本次完成的具体事项
- 参考 docs/ 目录结构确保进度与文档一致

### 2. 更新待办事项（.claude/todos/todos.md）
- 标记已完成的待办（`~~删除线~~ + ✅ 日期`）
- 添加本次新发现的待办（含触发时机说明）
- 移除已废弃的待办

### 3. 更新讨论记录（.claude/QA/）
- 如果本次会话有需求讨论、问题排查等内容，记录到对应的 QA 文件中
- 如果没有与项目相关的讨论内容则跳过

### 4. 更新设计决策（.claude/QA/decision/）
- 如果本次会话有架构或设计决策，在 decision 目录下单独保存
- 检查 decision 目录中的已有决策是否有冲突：
  - 冲突时以 .claude/QA 中原始记录的时间顺序为准
  - 时间在后面的记录为权威来源

### 5. 更新文档索引（docs/architecture/index.md 或项目对应索引文件）
- 如果本次修改了架构文档（新增/重命名/删除），同步更新索引文件

### 6. 完成确认
- 输出会话摘要（见下方模板）
- 确认所有文件已保存后，提示用户可以安全退出

## 输出模板

```
会话摘要：
- 完成：{1-3 句话概括本次完成的工作}
- 修改文件：{列出修改的关键文件}
- 遗留问题：{如果有未解决的问题，简要说明}

工作状态已保存，可以安全退出。
```

## 注意事项

- 只更新实际发生变化的内容，不修改未涉及的部分
- 保持现有文件格式一致（标题层级、日期格式、✅/~~标记）
- 如果会话中未产生实质性进展，可以跳过更新但仍告知用户
